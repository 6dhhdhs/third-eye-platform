# 第三只眼 · 数据库设计说明

> 依据：《PRD-第三只眼V1.2》第 11 章「数据结构与状态管理建议」+ 前端高保真原型实际字段
> 数据库：MySQL 8.4 · 字符集 `utf8mb4` · 引擎 InnoDB
> 脚本：[init.sql](init.sql)（可重复执行，不会清空数据）

---

## 一、设计原则

| 原则 | 落地方式 |
| --- | --- |
| 证据先于结论 | 标注表存时间戳 + 事实原文；报告表存 `evidence` JSON 回溯到标注 |
| 打卡按自然日唯一 | `daily_checkins` 对 `(user_id, local_date)` 建唯一键 |
| 量表版本不可篡改 | `lesson_plan_reports.rubric_version` 固定，历史报告不随规则调整而变 |
| 不得默认高分 | 三维分数与总分允许 `NULL`，表示"信息不足" |
| 教案仅本人可见 | 表不设可见性字段，由应用层鉴权控制，避免误公开 |
| 行为可追溯 | 所有核心表保留 `created_at` / `updated_at` |

## 三、实体关系

```
users ─┬─< learning_progress >─ lessons >─ courses
       ├─< learning_events ──< daily_checkins
       ├─< observation_annotations >─ observation_tasks >─ lessons
       ├─< observation_reviews >─ observation_tasks
       │        └─1:1─ observation_reports
       ├─< lesson_plan_submissions ─1:1─ lesson_plan_reports
       │        └─self: prev_submission_id（版本链）
       ├─< recommendations
       └─< xapi_statements
```

关系说明：

- `observation_tasks` 挂在 `lessons` 上——观察任务本质是"针对某节课的录像"
- `lesson_plan_submissions.prev_submission_id` 自引用，形成版本链；首版为 `NULL`
- `daily_checkins.qualifying_event_id` → `learning_events`，留痕"是哪次学习触发的打卡"，删除行为记录时置空而非级联删除

## 四、关键约束

| 约束 | 表 | 作用 |
| --- | --- | --- |
| `UNIQUE (username)` / `(email)` | users | 登录名唯一 |
| `UNIQUE (user_id, local_date)` | daily_checkins | 同一天不能重复打卡 |
| `UNIQUE (review_id)` | observation_reports | 一份评课稿一份报告 |
| `UNIQUE (submission_id)` | lesson_plan_reports | 一次提交一份报告 |
| `UNIQUE (statement_id)` | xapi_statements | statement UUID 幂等 |
| `PRIMARY KEY (user_id, lesson_id)` | learning_progress | 进度唯一 |

## 五、与前端字段的对应

| 前端 localStorage 字段 | 数据库落点 |
| --- | --- |
| `te.checkins.v1` → `dates[]` | `daily_checkins.local_date` |
| 评课页 `grade / subject / planTitle / lessonTitle / concern` | `lesson_plan_submissions` 同名列 |
| 评课页 `text / chars / fileName / version` | `text_content / char_count / file_name / version` |
| 观察工作台事件标签（教师提问…其他） | `observation_annotations.event_type` ENUM |
| 观察工作台时间戳 `15:42` | `observation_annotations.video_second`（转秒存储） |

> 原型用 `localStorage` 是演示手段；正式版改为调用后端接口写这几张表。

## 六、使用方式

首次启动容器时自动执行（`docker-entrypoint-initdb.d`）：

```bash
docker compose up -d
```

手动执行：

```bash
docker exec -i third-eye-mysql mysql -uroot -proot < db/init.sql
```

连接信息（Navicat）：

| 项 | 值 |
| --- | --- |
| 主机 | `127.0.0.1` |
| 端口 | `3306` |
| 用户 / 密码 | `root` / `root` |
| 数据库 | `third_eye` |

## 七、后续可扩展

- `xapi_statements` 迁到标准 LRS（如 Learning Locker），本表退化为本地缓存
