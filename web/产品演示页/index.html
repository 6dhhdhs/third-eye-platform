第三只眼

Third Eye

师范生智能学习与教学能力训练平台

学生观看真实课堂录像，边看边打点标注教学事件并撰写评课文本；平台从「注意、推理、表述」三个维度 刻画其课堂观察能力，定位每个人的观察盲区，据此靶向推送针对性训练任务，并支持与专家标注、 同伴观察结果的对比分析。

它不是替学生评课，而是评学生怎么评课——同一节课，学生打点的分布和编码偏好就是数据， 系统据此判出他的观察盲区在哪，再推训练。

项目理念：观察他人的课，练习自己的课，让教学成长有据可依 主题配色：低饱和蓝 #8FAFC8 + 纯白 #FFFFFF 本页依据：《智能学习平台 PRD 需求规范》V1.0（2026-10-08）
01

产品定位与立意

PRD 1.1 – 1.4 · 2.3

平台的分析对象不是「课堂」，而是看课堂的人。传统课堂分析工具替人评课，第三只眼评的是评课的人—— 这是本项目在答辩中反复强调的一层翻转。

1.1 立意对照

对比项传统课堂分析工具第三只眼
输入课堂录像课堂录像 + 你的观察打点
输出课堂分析报告你的观察能力画像
本质工具替人评课工具评的是「评课的人」

1.2 核心价值 PRD 1.2

看得清

从课堂录像中发现有教育意义的师生行为与教学事件。

说得明

利用事件证据解释课堂表现，而不是仅给出主观好坏判断。

练得会

上传自己的说课视频，获得结构化反馈与具体改进方向。

能坚持

通过每日学习打卡、学习任务和成长档案形成持续训练习惯。

1.3 差异化特色 PRD 1.3

核心特色常规学习平台的典型功能「第三只眼」的拓展设计
课堂学习视频播放、学习进度记录录像时间戳标注、教学事件分类、基于证据评课
教学能力训练观看示范课程观察能力三维反馈与专家标注对照
个人实践习题、作业提交自主上传说课录像并获取分维度 AI 辅助评价
学习反馈完成率与成绩课堂观察诊断 + 说课专项报告 + 进步记录
学习激励学习提醒有效学习后打卡、连续学习天数、七日学习日历

02

PRD 核心功能板块

PRD 3.3 · 4.2 · 5.1 – 5.10

共 10 个功能模块，分为 P0 核心 / P1 增强 / P2 扩展三档。其中 F-05 课堂观察与教学事件标注、F-07 AI 说课视频上传与评价 是平台的两个特色核心模块。

F-01

用户注册与登录

邮箱 + 密码注册登录，账号信息维护，密码找回列入 P1。未登录访问受保护页面先跳登录，成功后回到原目标页。

P0账号与身份
F-02

首页学习工作台

欢迎信息与今日学习目标、继续学习卡、课程与训练入口、每日学习打卡卡片，是进入平台后的总调度页。

P0学习入口
F-03

每日学习打卡

完成一项有效学习任务即获得当日打卡资格；以自然日为唯一键，同日不重复计次；连续天数中断不清零累计。

P0重点功能
F-04

课程学习

课程搜索与筛选、课程详情与章节目录、视频学习与进度记录、完成学习任务。

P0课程
F-05

课堂观察与教学事件标注

已授权课堂录像播放与时间定位；按事件类型打点标注（时间戳 / 事实 / 初步解释）；评课文本撰写并引用标注证据。

P0特色核心模块一
F-06

评课撰写与观察能力反馈

围绕「课堂事实—分析解释—改进建议」撰写评课；按注意 / 推理 / 表述三维输出观察能力反馈。专家参考标注对照为 P1。

P0P1 智能诊断
F-07

AI 说课视频上传与评价

选择说课主题、上传本人录像、本地预览与授权确认；按五维量表输出辅助评价报告与可定位的视频证据。真实解析为 P1。

P0 上传/预览特色核心模块二
F-08

个性化学习与训练推荐

针对已形成的有效评价结果，优先推荐最薄弱的一至两个维度；提供「为什么推荐」，用户自主决定是否参与。

P1推荐引擎
F-09

个人中心

个人资料、我的课程、学习打卡日历、课堂观察记录、我的说课作品与成长档案、隐私与数据管理。

P0成长档案
F-10

教师与平台管理

教师创建训练任务、维护专家参考标注、人工点评授权作品；管理员维护资源授权与账号基础状态。

P2 规划后台
03

核心模块关联

PRD 4.3

平台的两条训练主线各自闭环，再共同汇入薄弱项分析与个性化训练；而所有有效学习行为都会汇聚到每日打卡， 沉淀为个人成长档案。

主线一 · 课堂观察与评课

课程学习 ↓ 课堂录像观察 ↓ 教学事件标注 ↓ 评课提交 ↓ 课堂观察能力反馈（注意 / 推理 / 表述）

主线二 · AI 说课实训

自主录制说课 ↓ 上传视频 ↓ AI 辅助评价（五维量表） ↓ 可定位证据与改进建议 ↓ 再次实践

两线汇合 · 闭环

课堂观察能力反馈 + AI 说课辅助评价 → 薄弱项分析 → 个性化训练 → 再次实践
上述有效学习行为 → 达成今日打卡资格 → 每日打卡 → 成长档案

重要约束（PRD 5.6.2）：课堂观察三维反馈与 AI 说课五维评分是两套不同的能力体系，不得直接混算为单一分数。

05

状态设计

PRD 9.1 – 9.4 · 5.3.4 · 5.7.3

状态设计是本次前端作业的评分重点。以下三类状态在 PRD 中被逐条写死：统一状态规范七态、 每日打卡五态、说课视频处理四段流程。下方样例为纯静态呈现，用于说明每种状态应有的界面表现。

5.1 统一状态规范七态 PRD 9.2 · 全平台通用

① 初始态未选择课程 / 任务 / 文件
还没有正在学习的课程
浏览课程列表

要求：展示说明文字和明确入口，让用户知道下一步做什么。

② 加载态拉取课程 / 读取视频 / 处理报告
正在加载学习数据…

要求：展示加载指示及提示文字，不能只有一个转圈。

③ 空状态无课程记录 / 无标注 / 无历史视频
还没有学习记录
完成一次课程学习或课堂观察后，记录会显示在这里。
去课程学习

要求：说明原因并给出开始操作按钮，不将「暂时没有数据」渲染为错误。

④ 编辑态正在填写标注 / 评课 / 资料
观察事实（必填）
教师提出开放性问题后，等待了约 4 秒才点名…
保存标注取消草稿已自动保留

要求：允许保存 / 取消；必要时保留草稿；切换页面前提示未保存内容。

⑤ 成功态打卡 / 保存 / 上传 / 提交成功
✓今日打卡成功，连续打卡 1 天，累计 1 天。
✓ 今日已打卡

要求：文字提示 + 图标 + 状态更新三者齐备，并通过 aria-live 播报。

⑥ 失败态登录失败 / 上传失败 / 网络问题
!暂时无法保存，请重试。你的内容已保留在本地。
重试查看原因

要求：明确错误原因，支持合理重试，且重试不产生重复记录。

⑦ 禁用态条件未达成 / 正在重复提交
完成今日打卡 打卡按钮暂不可用：今天尚未完成任何一项有效学习任务。 去学习

要求：按钮禁用且说明无法操作的原因，不只置灰——这是最容易被做漏的评分点。

5.2 每日学习打卡状态机（五态） PRD 5.3.4 · F-03 重点功能

未登录

提交失败

统计与边界规则（PRD 5.3.5）

  • 每日最多计入一次：以自然日为唯一键，同日重复操作不增加天数。
  • 连续天数：今天已打卡则从今天向前连数；今天未打卡但昨天已打卡则截至昨天；更早中断从 0 开始。
  • 历史累计不清零：因此「累计打卡」与「连续打卡」是两个独立指标。
  • 不靠颜色单独区分：完成日同时给出对勾图标与 aria-label。

5.4 说课视频处理状态流 PRD 5.7.3

未选择文件→ 已选择待确认→ 上传中→ 上传完成
待分析→ 分析中→ 评价完成 ↘ 失败 / 可重试

纯前端原型不真实上传服务器时，流程改为：选择本地文件 → 格式校验 → 本地预览 → 点击「模拟分析」→ 显示「演示报告」， 不得展示伪造的真实服务器进度（PRD 5.7.3）。

5.5 关键异常场景 PRD 9.3

场景系统行为用户可执行操作
登录信息缺失高亮缺失字段并显示错误提示补全后重新提交

视频资源无权限 / 失效禁止非法访问，展示替代资源说明返回列表、选择其他资源
浏览器不支持视频编码提示格式 / 浏览器限制更换受支持文件或浏览器
标注正文为空禁止保存，聚焦必填字段填写内容
尚未完成有效学习打卡按钮不可提交，提供「去学习」完成任务

数据记录不存在展示 404 / 不可用提示返回安全页面

原型真实边界
